## 分级标准回顾

| 级别   | 判据                                              | 处理方式                                  |
| ------ | ------------------------------------------------- | ----------------------------------------- |
| 硬约束 | 改动破坏已上线/已分发客户端或生产数据，成本极高   | 默认保留；改动需单独论证 + 客户端同步升级 |
| 可探讨 | 改动影响内部实现或未启用客户端，但需同步文档/契约 | 里程碑开工前逐项确认                      |
| 自由   | 纯内部实现选择                                    | 直接决定，变更记录说明                    |

## 关键探讨点汇总（按里程碑归类）

### M2 身份认证（§6/§7/§8）

- Session 有效期、滑动策略、重认证窗口、缓存窗口
- 敏感操作清单边界（哪些操作要求 15 分钟重认证）
- Principal 载体规则是否需要简化

### M3 OAuth Provider（§10 未启用部分）

- Web/Mobile 客户端是否启用（决定 CORS、redirect URI、offline_access 策略）
- scope 命名与 audience 映射是否调整

### M4 业务 API（§9/§11/§12）

- API Key 期限上限、权限粒度、限流阈值
- Problem Details registry 是否精简

### M5 管理审计（§18）

- 事件类型、保留期、IP 指纹是否调整

### M6 备份运维（§19/§20）

- 备份频率、R2 界限、健康状态模型

### M7 SPA（§16）

- 页面结构、设计系统、同源部署是否保持

## 历史待定项（已由当前方案收敛）

1. server/client 是否拆为两个项目：当前采用单项目、同源部署，见 [架构规格 §3](architecture.md#3-部署与模块)。
2. Web/Mobile 客户端是否启用：当前 OAuth 客户端范围为 Desktop，见 [协议规格 §4.1](protocol-contract.md#41-clientredirect-与-continuation)；浏览器管理 SPA 仍属于产品范围。
3. 单仓库内是否用 pnpm workspace 分包：当前采用单 package，见 [架构规格 §3](architecture.md#3-部署与模块)。

Desktop 同步改版和放弃旧接口兼容已由 owner 确认，统一见 [架构规格 Q6](architecture.md#12-已收敛的需求选择更新至-2026-09-10)。当前需求选择已收敛，工程验证按验收规格执行。
